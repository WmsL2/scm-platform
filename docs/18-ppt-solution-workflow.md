# 类型 5 PPT 方案

## 业务流程

`创建项目 → DeepSeek 理解需求并选择受控类目 → 后端检索完整商品池 → 组织推品方案 → 人工确认 → 可选组套 → 完成选品 → Python 生成可编辑 PPTX → 下载/提交 → 中标或未中标`

类型 5 与类型 4 共用推荐 Run、候选和人工确认的基础设施，但选品策略和页面表现独立。DeepSeek 只做需求理解和受控类目选择，不对商品做“最多 30 条”的候选排序；类型 5 随后单独检索并冻结所有符合硬条件、类目选择和价格档的正式商品，作为本次方案的完整商品池。类型 4 的候选逻辑不受影响。

每次类型 5 Run 会按价格档生成可见的推品方案。价格档逐件检查商品的协议价，例如 100–200 元表示每件商品的协议价必须在该范围内，不计算、也不展示方案商品的总价。"每个方案商品数量" 是 AI 编排的目标件数，不是限制商品池只检索该数量；系统从完整商品池中组织不同方案。若价格档的完整商品池本身少于目标件数，该档不调用方案 AI，并明确提示调整条件或数量；若商品池充足但 AI 返回的有效商品少于目标件数，后端仍保存和展示该方案，并在方案卡标注“实际 / 目标”数量。每张方案卡可打开具体商品详情并确认其中商品；全量候选商品表不在类型 5 页面重复展示。用户可在待选品状态修改配置并重新生成新的 Run。

## 方案选择

- 点击“确认本方案商品”会在同一事务中确认方案内商品，并将该方案记录为已选。
- 已选状态保存在 `scm_ppt_solution_plan.is_selected`，同时记录 `selected_by` 和 `selected_at`；刷新页面、重新进入项目或完成选品后仍可识别。
- 方案列表接口返回选中状态；工作台以绿色边框、浅绿色背景和“已选方案”标签高亮。
- 当前选品模型允许选择多张方案，与既有“多次确认商品”的累加行为一致。未知方案、已锁定项目或当前不可用商品仍拒绝选择。
- 选择接口为 `POST /api/v1/ppt-solution-projects/plans/{plan_id}/select`，权限沿用 `recommendation:review`。

开始推品前必须保存配置：单品、组合或混合推品方式；至少一个价格档（只填最高价表示预算上限，填写最低和最高价表示价格区间）；每档候选数、每档方案数及可选履约截止日。配置以项目为单位保存并冻结到新 Run 的需求快照；履约日期不是商品主数据可验证字段，仍须人工核验。

## 生成方式

- DeepSeek 仅负责需求理解与受控类目选择；它不能访问数据库，不对商品做排序，也不直接生成文件。
- 价格档方案编排按“一个方案一次调用”执行。后端为冻结候选生成 `P0001` 形式的本次
  调用短引用，DeepSeek 只返回方案名称、说明和短引用列表；后端再映射为正式 Candidate ID，
  并复核数量上限、重复项、价格档及候选归属。短引用不落库，也不作为业务键。
- 单个方案结构化输出失败或返回未知引用、完全重复方案时，只重试当前方案一次；有效商品
  少于配置目标不会判定为任务失败，超过目标的部分由后端截断，
  不要求模型在一次响应中返回整个价格档的全部方案。
- 人工确认的单品、人工组合套装及其冻结价格快照由后端组装为生成输入；方案卡没有方案总价。
- Python 使用 `python-pptx` 在本机生成原生 `.pptx`，每个标题、文字和表格均是可编辑的 PowerPoint 对象，不把页面扁平化为图片。
- 类型 5 提供五套受控的系统内置版式：`SYSTEM_DEFAULT`、`JD_DETAIL_RED`、`JD_FESTIVE_RED`、`CATALOG_MINIMAL`、`UNION_QUOTE_WHITE`。用户只能从目录选择，不能上传或编辑模板，也不能传入文件路径。
- 创建生成任务时冻结 `template_code` 与 `template_version`；历史任务和未带模板编号的调用按 `SYSTEM_DEFAULT` 解释。任务不使用项目文件的 `template_file_id` 保存全局模板。
- 系统默认版保持 16:9 白底、顶部商品名称、左侧参数、中央分隔线、右侧商品图片；红白版保留红色封面和图文分栏，极简画册版使用左侧大图及右侧参数，工会报价版保留左右分栏与中央分隔线。每个单品或套装占一页，所有动态文字和图片均是原生可编辑对象。
- 四份业务样例只可放在受控部署/本地私有资产目录，禁止提交至公开仓库。四套业务模板会读取其审查后批准的 PPTX 标准商品页和（存在时）封面，按固定幻灯片/形状槽位替换商品字段和图片；原页的尺寸、主题、母版、布局、背景及静态图形关系保留。生产必须设置 `PPT_TEMPLATE_ASSET_DIR`；仅 development/test 可使用 Git 忽略的 `.codex-assets/ppt-template-sources/`。资产缺失返回明确错误，绝不退回低保真重绘。
- 生成前会删除未选的源业务页，并清空或替换所有被标记为动态的旧文本、图片和文本链接；缺图槽位显示“商品图片待补充”，不保留源客户商品图。未取得明确授权的品牌标识或装饰媒体不能被打包到公开资产中（ADR-0052）。
- 模板选择卡使用 `apps/web-admin/public/ppt-template-previews/` 下的 SVG 预览。预览只包含虚构保温杯、占位文案和虚构价格，按对应输出页的分栏与色彩绘制，不能替代客户样例或品牌素材。
- 超长规格、卖点和备注按固定字符预算拆成“详情续页”；商品名称和价格字段优先落在首页。人工确认活动价不存在时，页面显示“当前协议价”，不误称为活动价。
- 商品主数据的本地图片会自动插入右侧；套装最多展示四张商品图。未保存图片的商品明确显示“商品图片待补充”，不从外部 URL 下载或编造图片。

## 套装

- 只有人工已确认商品可以组成套装。
- 一个套装至少两种商品，可分别设置数量。
- 单价取人工活动价；未填写活动价时取候选冻结的协议价。
- 若填写价格档位，系统在保存时校验套装总价不得超过档位。
- 已进入套装的商品在生成输入中不再作为独立单品重复展示。

## 配置与边界

类型 5 与类型 4 共用 `DEEPSEEK_*` 配置。PPTX 渲染不需要 Kimi API Key、Agent ID 或外部 PPT 服务；部署环境只需安装项目依赖中的 `python-pptx`。

人工确认会重新检查 Product 为 `ACTIVE`、来源 Supplier 已归档且正常合作，以及 Run 的数值硬
条件。`ppt-v8` 的类目范围以本次 Run 已冻结并由 AI 选择的真实类目节点为准；确认阶段不得再用
客户原始类目文字做第二次包含匹配。
