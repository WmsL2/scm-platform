# 2. 供应商管理

## 2.1 供应商列表

筛选（真实 API）：

- 关键字：供应商编码、名称或主营品牌
- 归档状态
- 合作状态

表格：

- 供应商编码
- 名称
- 主营品牌
- 主要优势
- 归档状态
- 合作状态

操作：

- 查看详情；编辑和状态操作在详情页按后端返回的实时权限与状态机显示。

## 2.2 新增供应商

不显示 supplier_code 输入框。

保存成功后后端自动生成。

联系人、联系电话允许为空。只展示和维护已冻结的供应商名称、主营品牌、主要优势、联系人、联系电话；不展示来源旧编码、合作等级、税务、地址、银行或资质字段。

## 2.3 供应商详情

详情页展示系统编码、已冻结的基础资料、所有有效联系人、双状态和创建/更新时间；资质、产品报价、合作记录和操作日志依赖后续独立数据域与接口，不提前创建页面或字段。

## 2.4 供应商归档审核

提供提交归档、归档、停用、黑名单操作。仅在当前状态允许且账号具有相应权限时显示；停用和黑名单必须填写原因，所有状态机规则由 Supplier API 最终校验。

## 8.1 用户管理

表格只展示用户名、中文状态、所属角色和操作。状态统一显示为待审批、已启用、已禁用或已拒绝；
所属角色显示角色名称，未分配时显示“未分配角色”，不展示任何内部 UUID。账号具有
`system:user:role:update` 权限时，可在操作列打开“分配角色”弹窗，弹窗按角色名称选择并保留
真实 API 保存。只有状态为“已启用”的用户可分配或调整角色；待审批、已拒绝和已禁用用户不显示
该操作，后端也会拒绝绕过页面的角色写入请求。

## 8.2 角色权限

表格只展示角色编码、角色名称和操作，不展示权限内部 UUID。账号具有
`system:role:permission:update` 权限时，可在操作列打开“配置权限”弹窗；弹窗按权限名称选择，
仍由后端权限目录和角色权限替换 API 作为事实来源。

## 8.3 注册审批提醒

拥有 `system:registration:list` 权限的用户，左侧“注册审批”菜单显示待审批注册申请的红色数字。
数字来自真实注册申请 API 返回的待审批总数；没有待审批申请时不显示。批准或拒绝后，页面和菜单
数字会同步更新。

审批页面分为“待审批”和“审批历史”。待审批只显示可处理申请；审批历史按审批时间倒序、分页
展示已处理申请的用户名、审批结果、审批时间和审批说明。历史记录读取真实
`GET /api/v1/admin/registration-history`，不包含尚未审批的申请。
