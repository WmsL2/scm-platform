# 3. 商品当前成本价维护

一期不建设独立供应商报价列表、报价详情、报价历史、报价有效期或多供应商比价页面。

成本价维护属于“商品管理”的具体 Product 操作：具备 `product:cost:update` 权限的用户在目标商品上输入新的 `cost_price`；后端只保存成本价，其他价格、利润和比例保持原值。`source_supplier_id` 只展示为商品大表来源供应商，不表示当前报价供应商。

# 4. 商品管理

## 4.1 标准商品库

这里展示的是：

> 商品大表导入后的正式 `scm_product` 数据。

不是 Import Row。

列表常用区提供综合搜索、状态、查询、重置和“更多筛选”；高级区支持所属公司、采销员、品牌、供应商名称的包含查询，以及一级、二级、三级三个独立且可输入搜索的联动下拉框：一级限制二级、二级限制三级。候选项直接从当前可见商品主数据的三级类目路径生成，只显示实际可筛选到商品的选项；三级仍显示完整路径。另支持成本价、协议价、折扣率、销量的包含边界区间。所有条件按 AND 组合。综合搜索覆盖商品名称、品牌、型号、SKU、货号、69码、规格、卖点、三级类目、所属公司、采销员和供应商名称。

列表默认显示图片、SKU、商品名称、品牌、所属公司、采销员、类目、供应商、成本价、协议价、折扣率、销量、状态和更新时间；用户可自定义显示列，偏好仅保存在当前浏览器。

操作：

- 查看
- 编辑允许维护的字段
- 停用/恢复
- 更新当前成本价（具备 `product:cost:update` 权限时显示）
- 停用/启用（具备 `product:disable` 权限时显示）；已停用商品可由 `product:purge` 用户在二次确认后永久删除

商品列表使用页面正常纵向滚动；左侧导航栏固定于视口左侧。

## 4.2 商品详情

完整展示 43 列大表正式商品字段、来源供应商、当前 `cost_price` 与价格字段；不展示独立报价历史。普通编辑覆盖除供应商、SKU 和系统审计以外的业务字段，供应商与 SKU 只读。类目采用一级、二级、三级三个可搜索联动下拉框；图片只能上传文件替换或清除，不允许填写服务器路径。单独“修改成本价”只更新成本价本身。

## 4.3 商品大表导入

上传公司标准大表。

页面已实现 2026 固定 43 列 `.xlsx` 模板下载、上传、预览、供应商解析和 Confirm。导入页不创建供应商实体；供应商必须先存在于 Supplier Master，且为 `ARCHIVED + NORMAL + not deleted`。下载返回后端版本控制的批准原始模板，不依赖用户电脑路径。

商品大表默认允许最大 1GB / 100,000 行；上传和预览期间按钮保持加载状态，浏览器最长等待 15 分钟。超过配置上限时页面展示服务端返回的明确错误，而不是笼统的“Excel 预览失败”。

## 4.4 导入校验/预览

展示：

- 总行数
- 正确
- 错误
- 重复
- 冲突

可查看行级“通过（新增）/ 更新 / 不通过 / 已导入 / 已更新”状态、错误与警告，并按通过、更新或不通过筛选。固定 Excel 的 43 个表头必须完整有序；仅 SKU 与供应商必填，三级类目独立可为空，且不匹配 Category Master。通过行将新增正式 Product；同来源供应商 + SKU 命中正常 Product 的行显示为“更新”及其变更字段，确认后会覆盖该固定模板字段。价格仍使用固定大表的直接正式值，不通过系统公式复算。“确认新增/更新 N 行”只对当前无阻断错误且尚未处理的行可用；Confirm 前后会重新校验这些行的来源供应商和重复键，失败时本次不写入任何正式商品。不通过行始终保留在 Staging，绝不入库。

同一“来源供应商 + SKU”存在正常商品时，固定商品大表会将该行标为更新候选；更新保留正式商品 ID、创建审计、生命周期状态和业务键，其余 41 列覆盖，空单元格清空旧值。存在已停用商品时仍阻止导入，必须显式启用，或在永久删除后才能以新 Excel 创建同键商品；导入不会隐式恢复或启用商品。

对于 WPS/Excel 内嵌 `DISPIMG`，预览行显示“确认后保存”，不生成商品图片文件；Confirm 时仅当前实际写入正式 Product 的通过行提取并保存图片。重新导入替换或清空图片时，只在数据库事务成功后删除旧本地图片；全量 Confirm 后删除临时源 Excel。数据库只保存相对媒体引用，项目下 `local-data/` 的实际图片不进入 Git。

“供应商解析”区域按标准化供应商名称分组显示 Excel 原值、涉及行数、匹配状态、供应商编码/名称。`AMBIGUOUS`、`UNMATCHED`、`INELIGIBLE` 可打开“选择供应商”，仅显示当前 `ARCHIVED + NORMAL + not deleted` 的 Supplier Master；候选展示 supplier_code、supplier_name、main_brands。界面不突出 UUID，但提交的是 supplier_id UUID；同组只处理一次。解析后产生的通过行可继续导入，已经导入的行不会再次导入。

## 4.7 类目管理

类目管理维护既有 `scm_category` 三级路径维表，不提供任意层级分类树。页面入口需要
`category:list`；详情、新增、编辑、删除分别由 `category:detail`、`category:create`、
`category:update`、`category:delete` 控制。前端菜单、路由和操作按钮按实时权限显示，后端
仍通过 `require_permission` 强制校验；缺少权限返回 403。

商品新增/编辑使用的轻量类目选择接口仍属于商品用例，要求 `product:list`。类目 Excel
模板下载及导入继续属于商品导入准备流程，要求 `product:import`，本次不新增
`category:import`。删除仍受 Product 外键引用保护。

## 8.1 用户管理

表格只展示用户名、中文状态、所属角色和操作。状态统一显示为待审批、已启用、已禁用或已拒绝；
所属角色显示角色名称，未分配时显示“未分配角色”，不展示任何内部 UUID。账号具有
`system:user:role:update` 权限时，可在操作列打开“分配角色”弹窗，弹窗按角色名称选择并保留
真实 API 保存。只有状态为“已启用”的用户可分配或调整角色；待审批、已拒绝和已禁用用户不显示
该操作，后端也会拒绝绕过页面的角色写入请求。

## 8.2 角色权限

表格只展示角色编码、角色名称和操作，不展示权限内部 UUID。账号具有
`system:role:permission:update` 权限时，可在操作列打开“配置权限”弹窗；弹窗按权限名称选择，
仍由后端权限目录和角色权限替换 API 作为事实来源。

账号具有 `system:role:create` 权限时，页面右上角显示“新增角色”。弹窗要求填写创建后不可修改的
角色编码（小写英文开头，只能使用小写英文、数字和下划线）和角色名称；角色创建时不自动授予权限。
若账号同时具有权限目录和角色权限配置权限，创建成功后直接打开“配置权限”。本期不提供角色编辑、
停用或删除入口。

配置权限在保存期间会禁用复选框和保存/取消操作，避免并发覆盖。当前操作人修改自己所属角色时，
后端会确保其仍保留角色列表、权限列表和更新角色权限三项必要权限；如会导致当前账号失去角色管理能力，
保存将被拒绝并提示先由其他管理员接管。

## 8.3 注册审批提醒

拥有 `system:registration:list` 权限的用户，左侧“注册审批”菜单显示待审批注册申请的红色数字。
数字来自真实注册申请 API 返回的待审批总数；没有待审批申请时不显示。批准或拒绝后，页面和菜单
数字会同步更新。

审批页面分为“待审批”和“审批历史”。待审批只显示可处理申请；审批历史按审批时间倒序、分页
展示已处理申请的用户名、审批结果、审批时间和审批说明。历史记录读取真实
`GET /api/v1/admin/registration-history`，不包含尚未审批的申请。
