# 2. 供应商管理

## 2.1 供应商列表

筛选（真实 API）：

- 关键字：供应商编码、名称或主营品牌
- 归档状态
- 合作状态

表格：

- 供应商编码
- 名称
- 主营品牌
- 主要优势
- 归档状态
- 合作状态

操作：

- 查看详情；编辑和状态操作在详情页按后端返回的实时权限与状态机显示。

## 2.2 新增供应商

不显示 supplier_code 输入框。

保存成功后后端自动生成。

联系人、联系电话允许为空。只展示和维护已冻结的供应商名称、主营品牌、主要优势、联系人、联系电话；不展示来源旧编码、合作等级、税务、地址、银行或资质字段。

## 2.3 供应商详情

详情页展示系统编码、已冻结的基础资料、所有有效联系人、双状态和创建/更新时间；资质、合作记录和操作日志依赖后续独立数据域与接口，不提前创建页面或字段。

## 2.4 供应商归档审核

提供提交归档、归档、停用、黑名单操作。仅在当前状态允许且账号具有相应权限时显示；停用和黑名单必须填写原因，所有状态机规则由 Supplier API 最终校验。

# 3. 商品当前成本价维护

一期不建设独立供应商报价列表、报价详情、报价历史、报价有效期或多供应商比价页面。

成本价维护属于“商品管理”的具体 Product 操作：具备 `product:cost:update` 权限的用户在目标商品上输入新的 `cost_price`；后端按冻结公式原子重算派生价格和毛利，页面刷新后展示最新 Product 值。`source_supplier_id` 只展示为商品大表来源供应商，不表示当前报价供应商。

# 4. 商品管理

## 4.1 标准商品库

这里展示的是：

> 商品大表导入后的正式 `scm_product` 数据。

不是 Import Row。

筛选和表格列最终以真实大表字段为准。

至少支持：

- 商品编码
- 商品名称
- 品牌
- 型号
- 分类
- 状态
- 更新时间

操作：

- 查看
- 编辑允许维护的字段
- 停用/恢复
- 更新当前成本价（具备 `product:cost:update` 权限时显示）
- 停用/启用（具备 `product:disable` 权限时显示）；已停用商品可由 `product:purge` 用户在二次确认后永久删除

商品列表使用页面正常纵向滚动；左侧导航栏固定于视口左侧。

## 4.2 商品详情

完整展示大表正式商品字段、扩展参数、来源导入记录、来源供应商、当前 `cost_price` 与派生价格；不展示独立报价历史。

## 4.3 商品大表导入

上传公司标准大表。

页面已实现固定 `.xlsx` 模板上传、预览、供应商解析和 Confirm。导入页不创建供应商实体；供应商必须先存在于 Supplier Master，且为 `ARCHIVED + NORMAL + not deleted`。

## 4.4 导入校验/预览

展示：

- 总行数
- 正确
- 错误
- 重复
- 冲突

可查看行级错误与警告。三级类目和价格显示为固定大表的直接正式值，不要求匹配系统类目或通过系统公式复算。只有预览状态为 `READY_TO_CONFIRM` 时显示 Confirm；Confirm 前后会重新校验来源供应商，失败时不写入任何正式商品。

同一“来源供应商 + SKU”存在正常或已停用商品时均视为重复并阻止导入。停用商品必须显式启用，或在永久删除后才能以新 Excel 创建同键商品；导入不会恢复或覆盖已有商品字段。

对于 WPS/Excel 内嵌 `DISPIMG`，预览行显示“已保存”；Confirm 后商品详情展示可预览的本地图片。数据库只保存相对媒体引用，项目下 `local-data/` 的实际图片不进入 Git。

“供应商解析”区域按标准化供应商名称分组显示 Excel 原值、涉及行数、匹配状态、供应商编码/名称。`AMBIGUOUS`、`UNMATCHED`、`INELIGIBLE` 可打开“选择供应商”，仅显示当前 `ARCHIVED + NORMAL + not deleted` 的 Supplier Master；候选展示 supplier_code、supplier_name、main_brands。界面不突出 UUID，但提交的是 supplier_id UUID；同组只处理一次。全部解析完成且其余校验通过后才显示确认入口。

## 8.1 用户管理

表格只展示用户名、中文状态、所属角色和操作。状态统一显示为待审批、已启用、已禁用或已拒绝；
所属角色显示角色名称，未分配时显示“未分配角色”，不展示任何内部 UUID。账号具有
`system:user:role:update` 权限时，可在操作列打开“分配角色”弹窗，弹窗按角色名称选择并保留
真实 API 保存。只有状态为“已启用”的用户可分配或调整角色；待审批、已拒绝和已禁用用户不显示
该操作，后端也会拒绝绕过页面的角色写入请求。

## 8.2 角色权限

表格只展示角色编码、角色名称和操作，不展示权限内部 UUID。账号具有
`system:role:permission:update` 权限时，可在操作列打开“配置权限”弹窗；弹窗按权限名称选择，
仍由后端权限目录和角色权限替换 API 作为事实来源。

账号具有 `system:role:create` 权限时，页面右上角显示“新增角色”。弹窗要求填写创建后不可修改的
角色编码（小写英文开头，只能使用小写英文、数字和下划线）和角色名称；角色创建时不自动授予权限。
若账号同时具有权限目录和角色权限配置权限，创建成功后直接打开“配置权限”。本期不提供角色编辑、
停用或删除入口。

配置权限在保存期间会禁用复选框和保存/取消操作，避免并发覆盖。当前操作人修改自己所属角色时，
后端会确保其仍保留角色列表、权限列表和更新角色权限三项必要权限；如会导致当前账号失去角色管理能力，
保存将被拒绝并提示先由其他管理员接管。

## 8.3 注册审批提醒

拥有 `system:registration:list` 权限的用户，左侧“注册审批”菜单显示待审批注册申请的红色数字。
数字来自真实注册申请 API 返回的待审批总数；没有待审批申请时不显示。批准或拒绝后，页面和菜单
数字会同步更新。

审批页面分为“待审批”和“审批历史”。待审批只显示可处理申请；审批历史按审批时间倒序、分页
展示已处理申请的用户名、审批结果、审批时间和审批说明。历史记录读取真实
`GET /api/v1/admin/registration-history`，不包含尚未审批的申请。
