# Change Record：类型 5 推品方式与价格档配置

日期：2026-09-30  
分支：`codex/feat/type5-recommendation-modes`

## 变更

- 类型 5 工作台支持单品、组合、混合三种推品方式，以及多个最高预算或价格区间。
- 保存每档推品数量、每档方案数和履约截止日；开始推品前配置会持久化并写入 Run 需求快照。
- 类型 5 页面改为方案卡：不重复展示类型 4 的全量候选商品表；每张卡可打开该方案的具体商品详情并确认方案商品。手工组套仍保留在同页。
- DeepSeek 在类型 5 只做需求理解和受控类目选择，不再做商品候选排序；类型 5 随后冻结所有符合硬条件、类目选择和逐件协议价价格档的正式商品，再从完整商品池为每档生成指定数量的不同方案。每个方案商品数量只约束单个方案的商品数，不限制商品池检索量；方案可为避免完全重复而重叠取数。商品池不足单方案数量时不生成不完整方案。待选品状态可重新生成新的 Run。
- 类型 5 移除商品排序后，完整商品池建立路径允许 Run 从 `RETRIEVING` 自己进入 `RANKING`；该衔接只在类型 5 方法内，不改变类型 4 的状态机。任务失败时页面不再误显示“商品数量不足”。

## 数据库

- Revision `20260930_0043` 新增每项目一条的 `scm_ppt_recommendation_config`。
- Revision `20260930_0044` 新增 `scm_ppt_solution_plan`，保存本次 Run 的价格档、方案类型和商品集合。
- Revision `20260930_0045` 删除方案总价字段：价格档只按单件协议价筛选，不计算方案总价。

## 边界

- 履约截止日需人工核验；最终商品确认与手工组套继续沿用既有流程。
- 新增只读方案列表接口；复用既有 `recommendation:detail`，无新增权限。
