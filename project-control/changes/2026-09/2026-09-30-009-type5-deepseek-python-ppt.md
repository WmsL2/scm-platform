# 2026-09-30 类型 5 DeepSeek + Python PPT 重做

## 完成

- 类型 5 选品 Runner 改为使用既有 DeepSeek 结构化客户端，不再实例化 Kimi。
- 删除 Kimi 适配器、环境变量和单元测试；类型 5 与类型 4 共用 `DEEPSEEK_*` 配置。
- 新增本地 `PptRenderer`：以 `python-pptx` 生成可编辑的固定商品页，匹配已确认的客户参考版式（顶部标题、左侧参数、中央分隔线、右侧商品图）。
- 正式商品已保存的本地图片会自动插入；套装最多展示四张商品图。
- 类型 5 工作台金额改为固定两位小数显示，避免高精度 Decimal 原值撑破卡片；人工确认的未组套单品明确按“一件一页”生成，组套只用于合并多件商品。
- 工作台增加“完成选品并生成系统 PPT”，将状态推进和默认模板生成合并为一次操作；仍保留“完成选品”以便选择项目模板。
- 生成结果在页面顶部即时展示；成功后自动下载，同时保留“下载最新 PPTX”入口。后台派发或渲染异常会落为失败任务并显示失败类型，不再出现无提示的排队状态。
- 本机 `TASK_MODE=inline` 下，任务记录先以独立事务提交，再同步执行 Python 渲染，规避 FastAPI 响应后回调导致的 `RUNNING` 卡死；未来真实队列模式仍走后台派发。
- 修复生成完成后的隐式事务回滚：此前 `.pptx` 已写入本地存储，但 `SUCCEEDED`、导出文件关联和项目事件在 Session 关闭时回滚，页面因此永久显示“生成中”。
- 类型 5 创建页移除 PPT 模板上传，工作台固定使用系统默认模板；页面操作按模块收纳：选品按钮在“AI 推荐与人工选品”，生成与下载在“生成可编辑 PPT”记录表内，顶部只保留返回项目。
- 保留客户模板的已有页面，并将系统生成页追加在模板之后；无模板时使用系统默认商务版式。
- 生成任务继续保存 `PPT_EXPORT`、版本、校验和、下载关系与项目状态事件，不改动既有 API、权限或数据库表。
