# Change：类型 1 候选构建归一化缓存

日期：2026-10-14  
分支：`perf/type1-matching-speed`

## 变更

- 为类型 1/2 共用的 `normalize_match_text` 增加 65,536 项有界 LRU 缓存。
- 类型 1 在逐需求行扫描正式商品时复用商品品牌、型号、名称、规格和类目文本的归一化结果，不再重复执行 Unicode、大小写、全半角及分隔符处理。
- 不修改类型 1 召回证据、阈值、排序、完整候选分段、AI Prompt、协议价限价或全部合规商品输出规则。

## 验证

- 真实项目只读基准：265 行需求、7,257 条合规商品，候选构建由 80.439 秒降至 15.377 秒。
- 优化前后逐需求行候选商品 ID 和顺序完全一致；候选总数均为 1,628，最大单行候选数均为 158。
- 新增缓存边界与结果不变回归测试，并执行匹配模块 Ruff、mypy 和 pytest。

## 数据库 / API / UI / 权限

- Alembic Revision：无。
- API、UI、权限及数据库结构：无变化。
