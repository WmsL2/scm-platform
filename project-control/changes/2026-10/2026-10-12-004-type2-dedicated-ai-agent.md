# Change：类型 2 独立 AI 同品判断与动态模板理解

日期：2026-10-12  
状态：IMPLEMENTED / REAL_DEEPSEEK_ACCEPTANCE_PENDING

## 变更

- 新增类型 2 专属 `Type2Agent`、字段映射合同、需求/候选合同和结果合同。
- 未识别的类型 2 Excel 可由 AI 识别真实输入与输出列，服务端校验列存在后再解析。
- 匹配综合完整原始行、行备注与项目备注；完全同品优先，无完全同品才允许同类型替代。
- 替代结果强制记录差异备注；正式商品、供应商资格、限价、最低价及明确 88 折约束仍由代码校验。
- 导出只填客户结果列中的空单元格；工作台展示完全同品/替代类型和备注。
- DeepSeek 失败或合同错误会将任务恢复为 `IMPORTED`，允许重新执行。
- 类型 2 AI 编排使用独立短 Session 分阶段提交，不再对 FastAPI 请求依赖持有的外层事务执行 `rollback/begin`，修复启动匹配时的 `InvalidRequestError: closed transaction` 500。
- 类型 2 主流程收紧为“AI 识别重要列 → 代码按 SKU 或品牌+型号召回 → AI 仅复核附加条件 → 代码最低价回填”。缺少 SKU 且未同时提供品牌型号的行直接未匹配；无附加条件的标准行跳过 AI。替代仅在需求明确允许时开放。
- 需要 AI 的批次由串行改为最多四路受控并发，避免大表逐批串行等待。
- 商品搜索文本、搜索词、型号归一化和品牌别名目录改为每个匹配任务只构建一次，不再对每个需求行、每个商品重复拆词；单行 AI 候选由最多 20 条收敛为最多 8 条，降低 Prompt 体积。
- 并发批次任一失败时显式取消尚未结束的 DeepSeek 请求，避免 API 已返回失败后继续消耗时间与 Token。
- 类型 2 `READY` 项目允许重新执行匹配，保留历史选择审计并以新结果更新当前选择，便于旧逻辑项目直接复核而无需重新上传。

## 兼容性

- 无数据库 Schema 变化，无 Alembic Revision。
- API 路径与权限不变。
- 类型 1、3、4、5 的 Prompt、Agent 和流程未修改。

## 验证

- Ruff、Mypy、Bid/Matching 后端测试。
- 类型 2 专属 Agent Prompt/合同测试。
- 性能回归验证商品搜索文档按商品数而非“需求行 × 商品数”构建，并限制每行候选不超过 8 条；真实 288 行、7,246 商品只读基准候选构建为 9.614 秒，优化前约 80 秒。
- MySQL 集成测试验证原品 90 元仍优先于 50 元替代品；无原品行使用替代品并强制备注，测试数据已清理。
- MySQL 集成测试在与真实 API 相同的外层 `session.begin()` 中启动类型 2，验证独立编排 Session 不破坏请求事务。
- 前端类型检查、Bid 页面 Vitest 与生产构建。
- 真实 DeepSeek 和浏览器端到端验收待执行。
