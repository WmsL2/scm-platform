# Change：类型 1/2 跳过 Excel 汇总行

日期：2026-10-14  
分支：`perf/type1-matching-speed`

## 问题

最新类型 2 客户文件含 24 张工作表图片，工作簿及图片均可读取。创建失败实际发生在需求行数值转换：第 25 行为“合计”，数量单元格是公式 `=SUM(E2:E24)`，旧逻辑把该汇总行当成商品需求并将公式文本转换为 Decimal，返回“Excel 数量或限价格式不正确”。

## 变更

- 类型 1/2 共用需求解析在数量与限价转换前识别受控汇总行。
- 仅当已映射的商品身份字段全部由“合计、总计、小计、汇总”等标记组成时跳过；没有映射身份字段时，允许从原行精确汇总标记兜底识别。
- 商品名称即使为“合计”，只要同时具有真实商品编码等身份字段，仍按普通需求行保留。
- 不解析图片内容，也不改变含图片 `.xlsx` 的上传和原文件保存行为。

## 验证

- 新增汇总公式行回归测试，并覆盖同名真实商品不被误删。
- 问题原文件只读复算：保留第 2--24 行共 23 条需求，第 25 行合计不再进入数量转换。

## 数据库 / API / UI / 权限

- Alembic Revision：无。
- API、UI、权限及数据库结构：无变化。
