日期：2026-10-14

## 完成内容

- 取消 API 扩展支持 RUNNING 的协作式终止请求；PENDING 仍立即取消。保留请求人、请求时间和项目事件；重复请求幂等，停止确认前维持项目互斥。
- Worker 每秒检查终止请求，仅取消对应执行协程；解析/渲染线程退出并丢弃输出后才确认取消。PPT 渲染移入受限线程，停止/心跳轮询不再被渲染阻塞；未发布的文件在取消时清理，已提交文件保留。
- 删除单条后台任务记录的 API、前端入口、过滤逻辑和缓存重新入队分支已全部移除；任务历史保留，失败任务仍可重试。
- 新增项目级永久删除 API：项目有 PENDING / RUNNING 任务时拒绝删除；精确项目编号确认后，按外键依赖顺序物理删除项目拥有的需求、队列、匹配、推荐、类型 3、PPT、导出和事件记录，并在提交后尽力清理关联文件。
- 项目列表保留任务类型、取消/终止/重试入口，并增加“删除项目”二次确认；五类工作台共用状态面板和分页任务历史抽屉。
- 后端 `.env.example` 为任务相关配置补充中文说明，并将旧通用开关示例恢复为 `TASK_MODE=inline`：当前投标/推品 MySQL Worker 不读取该开关，避免误设为未配置的 ARQ 模式；HEAVY、心跳、租约和 MAPPING 并发均有明确作用范围及调优提示。
- 同步 ADR-0066、数据字典、模块状态与运行边界；用户 `.env` / `.env.example` 不变。
