# ADR-0044：自由推品类目分配文本识别

状态：ACCEPTED  
日期：2026-09-28

## Context

客户需求可能通过“家电 250、厨具 135、日用 115”明确表达本次要求的商品类目，也可能直接写出“需要水杯、保温杯、随行杯”。数字不是库存数量、采购下单量或候选数量上限；旧版 Type-4 因缺少“必须、仅限”等词会忽略这类类目名称，导致返回全部符合基础条件的商品。

## Decision

- Type-4 Requirement V6 将明确的“类目 + 数量”分配，以及“需要、要、采购、推品、需求”等直接提出具体商品类型的类目名称写入 `explicit_category_keywords`，并将原词及语义近义词写入 `category_intents`。
- 这类类目表达即使没有“必须、仅限”等字样，也属于明确类目要求；场景、用途、送礼和福利等词不作为类目。
- 数字一律不写入库存、下单数量、候选上限或开放池逻辑；服务端保留全部符合数值、品牌和语义类目硬条件的商品。
- 历史 V3/V4/V5 Run 保持原有结果与语义；短暂生成过的 V6 类目配额 JSON 仅读取其类目词并按本 ADR 的类目硬筛选执行，数字忽略。

## Consequences

- 数字不是库存约束、不创建订单、不扣库存，也不代表采购下单数量。
- AI 仍只调用一次以结构化解析需求；商品查询、语义类目匹配和候选持久化由后端确定性完成。
- 无新增表、无 Alembic Migration、无新增权限；复用 Run 的 `parsed_requirement` JSON。
