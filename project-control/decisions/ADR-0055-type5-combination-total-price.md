# ADR-0055：类型 5 组合推品按组合总协议价生成

状态：ACCEPTED
日期：2026-10-09

## 背景

类型 5 的直接选品已经支持按每件商品协议价筛选和人工确认。组合推品需要把价格档解释为一组商品的总预算，而不是每件商品的价格，并且每组必须包含多个商品。

## 决策

- 仅类型 5 的新 `COMBINATION` Run 使用本规则；类型 1--4 和类型 5 单品模式不变。
- 每条价格档的 `item_count` 在组合模式中表示 AI 需要生成的组合数；页面文案明确为“组”。
- 单档组合数上限为 100，避免最终 AI 比较请求失去 Token 边界。
- 每组固定由 2--4 个不同冻结候选组成；组合内全部使用冻结协议价，后端在 AI 调用前后校验组合总价落在该档 `[min_price, max_price]` 内。
- 后端先对可参与任一组合价格档的冻结来源商品进行一次场景与性价比评分，并复用于全部组合价格档；再使用受限 beam search 构造总价合规组合。AI 只从服务端签发的组合短 ID 中选择指定数量，不能计算或绕过价格规则。
- 最终组合持久化到既有 `scm_ppt_solution_plan`，以 `COMBINATION` 标识并沿用既有方案选择审计和人工确认权限。非最终组合商品会从候选结果裁剪，避免冻结全池被页面展示或确认。
- 本次不改变 PPT 渲染、PPT 套装创建和模板生成：确认组合仅确认该组合内商品并持久化选择审计。

## 后果

- 无新表、无 Alembic Revision、无新增权限；历史 `PLANS` Run 和新单品 `DIRECT` Run 保持原读取和执行分支。
- 组合候选采用受限搜索而不是枚举所有 2--4 件笛卡尔组合，避免大商品池的组合爆炸；候选不足时返回明确失败原因。
- 组合来源评分并发最多两路，以减少调用提供方时的限流风险；单品模式继续沿用原有并发设置。
