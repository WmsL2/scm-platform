# ADR-0013：商品逻辑删除与页面滚动布局

状态：SUPERSEDED BY ADR-0015
日期：2026-09-11

## 背景

业务需要在商品列表中删除不再使用的正式商品；同时保留后台页面原有的纵向滚动体验，并让左侧导航在浏览内容时持续可见。

## 决策

- 商品删除采用逻辑删除，不物理删除 `scm_product`、导入审计记录或本地图片文件。
- `DELETE /api/v1/products/{product_id}` 需要 `product:delete`；删除写入 `is_deleted`、`deleted_by`、`deleted_at` 和既有 `updated_by`。
- 正常商品列表、详情、基础资料编辑和成本价更新均过滤逻辑删除商品，并对已删除 ID 返回 `PRODUCT_NOT_FOUND`。
- `source_supplier_id + sku` 的数据库唯一约束保持不变。删除保留该业务键，不能通过删除绕过防重或静默重复导入。
- 左侧导航栏固定于视口左侧；商品列表保留页面正常纵向滚动行为，不在列表卡片内单独限制滚动区域。

## 结果

本次新增 `product:delete` 权限，系统管理员角色自动获授。删除为可审计的隐藏操作；如未来业务要求恢复或复用已删除 SKU，必须另行冻结恢复策略和 API。
