# ADR-0016：商品导入允许通过行分批确认

状态：ACCEPTED  
日期：2026-09-11

## Context

固定 32 列商品大表可能同时包含可安全写入的行和需要业务处理的错误行。原全批次 Confirm 要求全部行通过，导致已通过行也必须等待无关错误修正。

## Decision

- 预览按尚未导入的行统计“通过”与“不通过”；通过表示没有阻断型错误，警告仍保留展示但不阻止写入。
- Confirm 仅导入当前校验通过且尚未导入的行。不通过行绝不写入 `scm_product`，继续保留在 Staging 供查看和人工供应商解析。
- 每一次 Confirm 对本次所有通过行保持单事务原子性：确认时重新校验来源供应商和 `source_supplier_id + sku` 冲突；任一当前通过行失败，则本次不写入任何通过行。
- `scm_product_import_row` 保存 `is_imported`、`imported_by`、`imported_at`；`scm_product_import_task` 保存 `imported_rows`。已导入行不再参与后续校验与 Confirm，避免重复导入。
- Task 状态新增 `PARTIALLY_CONFIRMED`。所有行均已导入时为 `CONFIRMED`；仍有未导入行时，历史导入结果不被覆盖。
- 商品页面提供受 `product:import` 权限保护的模板下载，返回版本控制的原始 `商品大表模板.xlsx`，不得依赖开发机绝对路径或运行时拼装表头。

## Consequences

- Revision `20260911_0022` 增加导入行状态与任务累计计数，并把历史原子 Confirm 批次回填为已导入。
- 前端显示总行、已导入、通过、不通过，并支持全部/通过/不通过筛选；“导入通过的 N 行”在 N 为 0 时不可用。
- 修正 Excel 中不能通过的字段仍需重新上传；供应商匹配问题可在同一批次人工解析后继续导入剩余通过行。
- 本决策不引入 Excel 覆盖正式商品，也不改变停用商品或正常商品的同键防重规则。
