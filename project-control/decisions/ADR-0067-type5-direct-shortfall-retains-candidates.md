# ADR-0067：类型 5 单品价格档短缺时保留合格候选

状态：ACCEPTED  
日期：2026-10-16

## Context

类型 5 单品推品先冻结所有正式合格商品，再按每个页面价格档的目标数量执行 AI 评分与最终选择。旧行为在任一价格档的合格商品数少于目标时，将 Run 标记为失败并隐藏已经冻结的候选，运营人员既看不到实际可用商品，也无法确认它们继续生成 PPT。

价格档数量是期望的匹配数量，不应抹除已经通过正式商品、供应商、类目及价格档条件的商品。类型 5 `COMBINATION` 已采用“短缺时保留可用组合”的原则。

## Decision

- 仅新的类型 5 `SINGLE` 直接选品 Run 适用本规则；类型 1--4、类型 5 组合模式和历史 Run 保持不变。
- 若任一价格档合格商品少于其 `item_count`，不调用 AI 选品，也不将 Run 标记为失败。
- 后端保留本 Run 已冻结的全部合格候选，写入短缺提示，并转换为 `WAITING_CONFIRMATION`，允许人工逐件或批量确认。
- 短缺提示必须指出每个不足价格档的可用数和目标数，并说明已保留全部合格商品。
- 前端继续显示该警告，同时显示候选表、确认控件和后续 PPT 生成路径；不能将“候选不足”伪装成 AI 已按目标数量匹配完成。
- 若候选数为零，既有无候选终态保持不变；提供方、合同或其他运行失败仍按失败路径处理，不能借此开放人工确认。

## Consequences

- 用户可在候选不足时使用现有合格商品完成选品和生成 PPT，也可选择重新生成或调整价格档。
- 未进入 AI 排序的保留商品不写 AI 评分，候选原因明确标记为价格档短缺保留。
- 无新表、Alembic Revision、API 路径、权限或新增 UI 配置项；复用现有候选分页、人工确认与 Run 错误提示字段。
