# ADR-0065：投标项目受确认永久删除

状态：ACCEPTED  
日期：2026-10-15

## 背景

投标项目列表会积累测试、失败和不再需要的项目。只隐藏列表行会保留项目需求、匹配候选、推荐 Run、导出记录和附件，既影响后续排查，也不能满足明确要求的“从数据库彻底删除”。

项目数据与正式商品、供应商和可复用投标模板存在引用关系，不能依赖 MySQL 级联或直接删除 `scm_bid_project`。

## 决策

- 提供 `DELETE /api/v1/bid-projects/{project_id}`，请求体必须携带与当前项目完全一致的 `confirm_project_code`；不一致时拒绝，不进行任何删除。
- 复用既有 `bid:void` 权限；项目列表仅向具备该权限的用户显示“删除项目”。
- 在同一数据库事务中按外键反向依赖顺序物理删除项目专属的匹配任务、候选、人工选择、类型 3/4/5 Run 与候选/确认/方案、PPT 任务、导出记录、项目模板映射、项目文件、需求行和事件，最后删除项目本体。
- 不删除正式商品、供应商、类目或可复用 `BidTemplate`；这些不是单个项目独占的数据。
- 项目文件的本地/对象存储键在删除流程中逐个尽力清理。存储清理失败只记录日志，不能使已删除的数据库项目恢复。
- 项目列表不再显示“需求总数”和“匹配处理数”；它们不再是列表层面的运营信息。

## 后果

- 删除不可恢复，前端使用项目编号输入框二次确认；删除成功后重新加载当前列表页。
- 无 Alembic Revision、无新表、无新增权限数据。
- 正在执行的 inline 操作不会重新创建已经删除的项目；若它在删除后才提交，会因项目不存在失败，调用方应重新创建项目后再执行。
