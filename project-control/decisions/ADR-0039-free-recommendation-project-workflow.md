# ADR-0039：类型4自由推品项目状态由业务动作推进

- 状态：Accepted
- 日期：2026-09-28

## 决策

类型4自由推品项目沿用 `scm_bid_project.status`，不新建平行状态字段。状态按以下流程推进：

`IMPORTED → MATCHING → SELECTING → READY → EXPORTED → SUBMITTED → WON / LOST`

- 前三阶段由创建项目、启动 Agent 和候选生成自动推进。
- 终止态 Run 未生成新候选时不得让项目滞留在 `MATCHING`；有历史候选恢复 `SELECTING`，否则恢复 `IMPORTED`。
- `READY` 由运营完成选品触发，`EXPORTED` 由成功生成确认结果触发，`SUBMITTED` 和最终结果必须由运营明确确认。
- `READY / EXPORTED` 可受控回到 `SELECTING` 调整；该动作写入项目事件。已生成文件作为历史版本保留，不能覆盖或静默删除。
- AI 只产生候选和排序建议，不直接决定人工选择、投标提交或中标结果。

## 原因

项目状态必须表达真实业务进度，而不是可任意选择的展示字段。自动阶段避免操作人员重复维护状态；完成选品后的人工动作具有业务责任和外部事实，必须显式确认并写审计事件。

## 影响

- 项目列表不能以通用状态下拉越级修改类型4状态。
- 工作台需同时保留 Agent 候选和人工选择结果，并根据项目状态控制编辑与操作入口。
- 导出只消费人工确认记录；重新调整后必须生成新版本文件。
- 无 Schema 变化，无 Alembic Revision。
