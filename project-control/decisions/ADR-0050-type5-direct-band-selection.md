# ADR-0050：类型 5 按价格档直接匹配并人工勾选

状态：ACCEPTED
日期：2026-10-09

## 背景

类型 5 以前使用全局“每个方案商品数量”和“每档生成方案数”，为每个价格档生成多张方案卡，再由用户选择方案。该交互不符合按价格档直接获得一批商品并逐件确认的业务方式。

## 决策

- 每个价格档保存 `min_price`、`max_price` 和 `item_count`；不再向新配置暴露全局方案数量或每方案商品数量。
- 价格档必须不重叠，避免同一商品同时占用两个价格档的数量。
- Agent 仍负责需求理解和受控类目选择；在冻结的正式商品池中，每个价格档只进行一次 AI 商品匹配，后端从同档冻结候选补齐或截断到该档 `item_count`。
- 新 Run 仅保留所有价格档匹配出的这一份候选清单，页面复用类型 4 的候选表、列选择与复选确认交互；不显示方案卡、方案选择或方案详情弹窗。
- 套装和 PPTX 生成继续基于人工已确认商品，不受此交互变化影响。
- 历史 Run 以冻结快照的 `selection_mode=PLANS` 保持原方案卡生成和读取能力；新配置冻结为 `selection_mode=DIRECT`。

## 后果

- 既有 `scm_ppt_solution_plan` 和历史方案选择审计不删除；新直接选品 Run 不创建方案记录。
- 不新增数据库表或 Migration；价格档数量和模式保存在既有 JSON 配置与 Run 快照中，旧配置读取时按原全局数量兼容显示。
- 新 Run 的候选行数量等于每个价格档 `item_count` 之和；人工确认仍沿用 `recommendation:review`。
