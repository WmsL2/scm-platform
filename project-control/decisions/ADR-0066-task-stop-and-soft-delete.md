# ADR-0066：后台任务协作式终止与项目永久删除

状态：ACCEPTED
日期：2026-10-14

## 决策

- PENDING 任务取消立即进入 CANCELLED；RUNNING 任务只记录终止请求，Worker 停止本次协程并等待其受限解析/渲染线程退出后，再确认 CANCELLED。
- 不杀共享 Worker，不通过手工数据库 UPDATE 模拟停止。终止请求未确认前仍占用项目 HEAVY 互斥；心跳继续维持租约且不覆盖“正在终止”提示。离线 Worker 的过期终止请求由租约扫描收敛。
- Revision `20261014_0060` 仅新增 `cancel_requested_at/by` 两个可空审计字段，不扩展既有 status CHECK；曾短暂存在但未投用的任务软删除字段由 Revision `20261014_0061` 移除。界面以 RUNNING + 请求时间显示“正在终止”。
- 后台任务没有单条删除入口；已结束任务保留在项目任务历史中，可重试失败任务。
- `DELETE /bid-projects/{project_id}` 是项目级物理删除：复用既有 `bid:void`，要求精确项目编号二次确认，拒绝存在 PENDING / RUNNING 任务的项目。在同一数据库事务内按外键依赖顺序删除项目拥有的需求、队列、匹配、推荐、类型 3、PPT、导出和事件记录；提交后尽力删除关联对象存储文件。
- 终止仅阻止后续执行和未提交结果；已经提交的结果保留。完成与终止竞争时，已先完成的任务可以保持成功。远程模型的实际计算/计费不能由本机强制撤销。
- 操作权限沿用任务类型对应的匹配、推品、导出或映射权限；列表和工作台共用按钮、确认提示与历史记录入口，不新增权限码。

## 后果

- 在解析或渲染期间，终止可能需要等待当前步骤结束，不能承诺瞬间停止。
- 部署必须迁移并统一重启 API 与两个 Worker；混用旧 Worker 不支持终止确认。
- 项目永久删除不可恢复，且不会保留项目自身的数据库审计/任务历史；对象存储与数据库不能组成跨资源原子事务，因此存储清理异常会记录告警而不回滚已提交的数据库删除。
