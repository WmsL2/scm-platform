# ADR-0069：类型 1 多商品按动态回填字段横向展开

状态：ACCEPTED
日期：2026-10-16

## 背景

类型 1 的一条规格需求会保留全部合规商品。ADR-0060 规定第一件商品写入原需求行、后续商品复制并插入新行，但正式报价表要求原需求行数和顺序保持不变；同一需求的多个商品应在该行右侧连续展示。

每个客户 Excel 的回填字段均不同，字段由当前项目的 AI 建议和人工确认共同确定，不能在代码中固定为某套供应商报价、SKU、品牌或备注列。

## 决策

- 类型 1 不再插入或复制需求行，客户原表行数、需求内容和原始顺序保持不变。
- 第一件合规商品继续写入客户原表已有的回填列。
- 第二件及后续商品在工作表最右侧依次追加完整回填列组，并写入同一需求行。
- 每组字段严格来自当前项目已确认的输出映射；字段数量、名称和语义均不写死。追加列按原回填列在客户表中的实际列顺序排列。
- 只复制已映射的回填列，不重复需求输入列或其他未映射列。
- 追加列复制原回填列的表头、表头区域内容、列宽、隐藏/分组属性和逐行单元格样式；数据区不复制其他需求行的原值，未使用的商品组保持空白。
- 原回填单元格已有客户内容时仍不覆盖。横向新增组为空白列，按匹配顺序写入对应商品冻结快照。
- 工作簿需要追加多少组，以当前类型 1 项目中单行最大合规商品数决定；匹配数量较少的行，其多余商品组保持空白。
- 类型 2 保持一行一个最低合规商品的既有规则，不使用横向多商品列组。

## 后果

- 本 ADR 仅替代 ADR-0060 中“后续商品在原需求行下复制插入新行”的导出布局；类型 1 全部合规商品、AI 分批复核、协议价限价、Selection 快照和页面匹配行优先展示规则继续有效。
- 不新增数据库表或字段，无 Alembic Revision。
- API 路径、权限、匹配准确度和类型 2 流程不变。
- 工作表列数会随单行最大匹配数量增加，真实复杂表头和打印区域仍需浏览器下载后验收。
