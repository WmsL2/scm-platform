# ADR-0056：类型 5 组合全局去重与可用结果保留

状态：ACCEPTED
日期：2026-10-12

## 背景

ADR-0055 的组合生成以每个价格档独立选组。虽然每个组内的商品不重复，但不同组（包括不同价格档）之间没有共享的已占用商品约束，导致同一商品反复出现在多张组合卡中。旧逻辑还把“无法生成配置数量”视为整次失败，隐藏了已经可用的组合。

## 决策

- 仅新类型 5 `COMBINATION` Run 使用本规则；类型 1--4、类型 5 `SINGLE`、历史 Run 和 PPT 渲染合同不变。
- 后端按价格档顺序维护本 Run 的全局已占用 `product_id` 集合。每个组合内、同一价格档之间和不同价格档之间均不得重复商品。
- 商品仍先经过全冻结池的压缩场景/性价比粗评；后端以粗评分、价格档和类目多样性构造受限的无重复组合短名单；AI 只在该详细短名单中进行最终相关性、互补性和价值精评。确定性阶段不替代 AI 的相关性排序。
- 组合候选搜索仍有上限，避免枚举全部 2--4 件排列；组合评分并发遵循配置上限且最多四路。
- 请求数量是目标，不是必须成功的门槛。只要至少有一组总价合规且全局无重复的组合，就持久化、展示和允许人工确认；工作台明确展示“已生成 / 目标”和不足提示。只有零组可生成才进入失败路径。

## 后果

- 无新表、无 Alembic Revision、无新增权限或外部 API 合同；既有组合计划和人工确认审计继续复用。
- 组合不足不再导致已生成组合丢失；人工可直接确认可用结果、完成选品并生成 PPT。
- 实际生成时长仍受候选规模、提供方吞吐和限流影响，不承诺固定秒数；需要用真实 DeepSeek Run 和浏览器工作台复验吞吐与短缺提示。
