# ADR-0052：类型 1–3 业务类型与内部处理引擎分离

状态：ACCEPTED  
日期：2026-10-09

## 背景

历史合同仅用 `FILTER_RECOMMENDATION` 表示类型 1–3，无法表达三类业务的真实差异：

- 类型 1 按规格参数逐行匹配，允许在满足参数和限价时推荐其他品牌；
- 类型 2 按品牌、型号或 SKU 识别同品、自动取最低有效当前成本价，并回填客户原表；
- 类型 3 按指定三级类目批量筛选和多选商品，不是一行需求只选一个商品。

## 决策

- `scm_bid_project.recommendation_type` 保存用户看到的类型 1–5；历史无法判断的
  `FILTER_RECOMMENDATION` 项目保持 NULL，不猜测类型。
- `project_type` 继续表示内部引擎：类型 1/2 使用逐行匹配引擎，类型 3/4 使用批量推荐引擎，
  类型 5 使用 PPT 引擎。
- 类型 1 的兜底召回允许品牌替换，但型号冲突仍是硬冲突；类型 2 只接受 SKU 或品牌+型号精确同品，不做语义替代。
- 类型 2 由用户在工作台显式启动匹配；多个同品按正式商品当前成本价选择最低正数且不超过客户限价的商品。没有有效同品即保留 `NO_MATCH`，不进入逐行人工确认，项目可直接导出。
- 类型 1/2/3 与类型 4 统一采用“上传并创建 → 进入工作台确认输入 → 用户点击开始 → 查看和确认结果 → 导出”的前端节奏。进入工作台不得自动执行任务。项目详情保留为辅助审计入口，但不是主流程必经页面；类型 1 仅保留候选确认与无法报价处理，类型 2 结果只读。
- 已确认的中信特钢、北京烟草、光明商业模板使用确定性表头 Profile，不让 AI 猜导入表头。
- 类型 2 导出回填原工作簿；重复表头按物理出现序号区分。
- 类型 3 上传模板时从非“参考”Sheet提取明确三级类目；不上传模板时使用商品大表标准模板并自动确认映射。
- 类型 3 写入映射列时不得覆盖客户模板中未映射的类目区域。

## 数据库

Revision `20261009_0052` 新增可空 `recommendation_type` 和受控 Check Constraint，并仅对能
确定类型的历史类型 4、5 项目回填。

## 后果

- API 创建项目可传 `recommendation_type`，并校验它与内部 `project_type` 一致。
- 前端创建页展示五张独立类型卡片。
- 任意新客户模板的人工输入字段映射、类型 3 多 Sheet 分组导出、B/C 品来源及折扣规则仍需后续实现。
