# ADR-0048：类型 5 使用短引用逐方案编排

状态：ACCEPTED
日期：2026-10-08

## 背景

类型 5 原实现将一个价格档的全部冻结候选一次性交给 DeepSeek，并要求一次返回该档所有方案的完整 UUID 列表。候选池达到上千件、单方案达到数百件时，请求和结构化响应过大，模型容易返回截断 JSON、错误数量或不符合 Schema 的内容。

类型 5 `ppt-v8` 在人工确认时还被通用复核错误地当成旧版类目文字匹配，导致已通过真实类目树召回的候选全部被判为不可用。

## 决策

- 每个价格档仍向方案 AI 提供全部符合条件的冻结候选，但采用紧凑列数组，并为本次调用生成 `P0001` 形式的短引用；不向模型暴露 Candidate UUID。
- 一个方案对应一次结构化调用。模型只返回方案名称、说明和短引用，不返回 SKU、供应商或完整商品对象；配置数量是模型应尽量满足的目标，不是方案持久化门槛。
- 短引用只存在于调用内。后端将其映射回冻结 Candidate ID，校验未知引用、数量上限、方案内重复、方案间完全重复、价格档和候选归属后，继续按既有表结构保存真实 Candidate ID。模型少选时保存实际有效商品并由页面标注“实际 / 目标”数量，模型多选时截断到配置上限。
- 结构化输出或后端合同校验失败时，仅重试当前方案一次；安全错误摘要写入服务日志，不记录 Provider 原始响应或完整 Prompt。
- `ppt-v8` 与 `v8` 一样，类目范围只使用 Run 已冻结的真实类目节点。人工确认仅复核商品、供应商及数值硬条件，不再使用客户原始类目文字二次筛选。

## 后果

- 单次响应最多承载一个方案，现有每方案 500 件上限可继续由后端 Schema 强制。
- 商品池本身不足目标数量的价格档仍不调用方案 AI；商品池充足但 AI 少选时不再导致整批方案消失。
- 数据库仍保存真实 Candidate ID，历史方案和下载流程不变；无需 Migration。
- API 和权限合同不变；类型 5 方案卡增加实际/目标数量提示，类型 4 流程不受影响。
