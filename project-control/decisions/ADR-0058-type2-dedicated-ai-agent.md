# ADR-0058：类型 2 独立 AI 同品判断 Agent

状态：ACCEPTED  
日期：2026-10-12

## 背景

类型 2 的客户表并不只有品牌和型号。同一型号可能因颜色、适用机型、打印量、包装规格、计量单位或行备注不同而代表不同采购项；不同客户模板的表头和结果列也不固定。仅依赖固定模板与品牌型号字符串会漏推或错推，同时不能满足“原品优先、无原品才允许同类型替代并注明差异”的业务规则。

## 决策

- 类型 2 使用独立封装的 `Type2Agent`、独立 Pydantic 合同和独立 Prompt 版本；不得复用类型 1、3、4、5 的业务 Prompt 或选品 Service。
- 未识别的类型 2 工作簿由该 Agent 识别真实 Sheet、表头行、输入列和空白结果列。AI 只能选择工作簿中实际存在的列；服务端再次校验后才冻结为模板映射。
- 类型 2 的主匹配入口固定为客户商品编码，或品牌和型号；品牌/型号继续使用受控确定性归一化。品牌与型号可来自独立列，也可从商品名称或规格参数全文中唯一、安全地提取；无法唯一确定时保持未匹配，不猜测。
- AI 首先负责未知模板的重要列识别。匹配阶段只接收代码按 SKU 或品牌+型号召回的候选，并复核颜色、适用机型、容量/打印量、包装、单位及备注等重要条件；完整原始行、重要字段、项目备注和候选均使用受控结构。AI 不得创造商品、SKU 或候选引用，也不得改变品牌型号主匹配入口。
- `EXACT` 以客户商品编码或受控归一后的品牌+型号为主条件。正式商品有可比较信息且与客户已填写要求明确冲突时必须排除；商品侧字段不存在、字段为空或文本未提及只表示未知，不得仅因缺少证据排除，也不得宣称未知属性已经验证满足。预计数量不参与同品判断。即使编码命中，已有品牌、型号或商品属性明确冲突时仍必须排除。
- 没有附加条件且编码、品牌和型号均无冲突的唯一/同型号候选可直接由代码进入最低价选择。存在商品名称、规格参数、有效备注等附加条件、候选歧义，或明确允许替代且代码无同品时才调用 AI；空白结果列与预计数量不会送入身份复核。商品搜索文档与品牌目录按任务一次构建，每行只向 AI 暴露确定性排序后的前 8 个候选，AI 批次最多四路并发。任一批失败必须取消同轮尚未完成的提供方请求。
- 只有客户需求或项目备注明确允许替代，且不存在满足全部条件的完全同品时，服务端才考虑 AI 标记的同类型替代品。替代备注必须以“同类型商品替代：”开头并说明实际差异，否则整批 AI 结果拒绝落库。
- 最终价格口径已由 ADR-0062 明确为协议价；本 ADR 原有“正价格、客户限价、最低价”表述均按协议价执行。商品资格、供应商状态和明确的折扣约束仍由确定性代码校验。折扣比例不是固定 88 折开关，而是从项目备注和非空需求单元格动态解析；支持小数、百分比及“折”表达。空白结果列即使表头包含比例也不构成约束；非空结果/要求单元格可连同其表头参与解析。
- 完全同品始终优先于替代品，即使替代品价格更低。最终选择、快照、替代备注及审计事件由服务端事务写入；AI 不直接写正式业务库。
- 导出保留客户原工作簿，只填写映射结果列中的空白单元格，不覆盖客户已有报价或备注。商品主数据没有可靠价格有效期字段时保持为空，不推测日期。

## 后果

- 类型 2 可适配品牌、型号位于独立列或参数全文的不同客户模板，并利用有效行备注与项目备注减少误判。
- 商品主数据缺少客户侧附加字段时不会漏掉品牌型号已命中的原品；商品已有事实明确冲突时仍不会乱推。
- 工作台明确展示“完全同品 / 同类型替代”和匹配备注。
- DeepSeek 未配置、调用失败或结构化输出不合规时，任务回到可重试状态并返回类型 2 专属错误，不产生半成品选择。
- 不新增表、字段或 Alembic Revision；API 路径和权限不变。
