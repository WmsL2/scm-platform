# ADR-0064：类型 1/2 输入映射确认先于需求解析

状态：ACCEPTED  
日期：2026-10-14

## 背景

类型 1/2 客户 Excel 的 Sheet、表头位置和列名会变化。此前专属 Agent 的输入映射建议在项目创建请求内直接用于需求解析，用户只能复核结果回填列，无法在商品匹配前纠正需求列语义。输入映射错误会影响商品名称、品牌型号、规格、限价和备注等正式匹配依据。

类型 4 的模板字段确认提供了合适的交互方向，但类型 1/2 不能复用类型 4 的业务流程、字段合同或推荐规则。

## 决策

- 类型 1、2 继续使用各自独立 Agent、Prompt、输入字段合同和匹配编排，只复用纵向映射确认的交互形式。
- 创建项目时保存 ORIGINAL、项目专属 `BidTemplate` 和 AI 建议；不创建 `BidProjectItem`，项目导入状态保持 `MAPPING_REQUIRED`。
- 人工可调整 Sheet、表头行、数据起始行，并逐列确认“客户 Excel 列 → 类型专属需求字段”。确认时服务端必须从该项目 ORIGINAL 重新读取并校验真实表头、一列一义和类型主匹配条件。
- 人工确认的映射只定义结构化主参考字段，不是输入白名单。原表中未映射的其他非空列继续完整保存于 `source_data`，并作为 `source_row` 次要上下文传给对应类型 Agent；次要字段可补充明确要求和冲突证据，但不得取代主条件、扩大代码召回或绕过硬规则。
- 校验通过后才生成需求行并将导入状态改为 `PARSED`；开始匹配的门禁顺序为输入映射/解析完成、结果回填映射确认、项目状态允许。
- AI 结构化建议失败时，只从当前工作簿确定人工映射入口的初始 Sheet 与候选表头，不猜测字段语义，不读取其他项目模板。
- 历史项目若仍引用共享模板，首次确认输入映射前必须复制为该项目专属模板快照，禁止原位修改共享模板。
- 输入映射和 ADR-0061 定义的输出回填映射继续分离；修改输入映射不改变类型 1 全部合规商品输出、类型 2 原品优先/替代兜底、协议价限价或导出只填空白格等规则。
- 确认事件写入既有项目事件表；确认状态使用既有 `import_status`，映射使用项目专属 `BidTemplate.import_mapping`，不新增数据库字段。

## 后果

- 新增 `GET/PUT /api/v1/bid-projects/{id}/input-mapping`，分别复用 `bid:detail` 和 `bid:update`。
- 无 Alembic Revision，无新增权限。
- 新项目多一个必须由用户完成的确认步骤；换取匹配依据可见、可纠正且项目隔离。
- 真实 DeepSeek 与浏览器全流程仍需验收。
