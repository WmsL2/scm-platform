# ADR-0019：投标项目核心与文件版本

状态：ACCEPTED
日期：2026-09-15

## 背景

投标业务以“一个买家 Excel 对应一个投标项目”为固定边界。源文件必须可追溯且不可覆盖，报价文件需要按版本保存。当前尚未提供真实买家样表，因此不能假设具体表头或报价列。

## 决策

- 新增投标项目、模板、项目文件、项目需求行、项目事件、匹配任务、候选商品、人工选品八张表，由同一条 Migration `20260915_0024` 创建。
- 项目生命周期固定为 `IMPORTED → MATCHING → SELECTING → READY → EXPORTED → SUBMITTED → WON / LOST`。
- 模板解析状态独立于项目生命周期，使用 `PARSED`、`MAPPING_REQUIRED`、`FAILED`；未识别模板时仍保存项目和 ORIGINAL 文件，等待后续配置映射。
- ORIGINAL 文件永不覆盖；报价文件从 ORIGINAL 副本生成并按版本新增。重新选品后项目回到 `READY`，必须重新导出新版本；已投标项目不允许改选。
- 项目需求商先保存为普通文本，不新增客户主数据模块。
- 报价写入列由模板配置控制；当前没有真实样表，不预置或猜测客户字段。
- 项目使用 `BID_PROJECT` 业务序列生成编号；新增投标权限并默认授予现有管理员角色 `boss`。

## 原因

该方式既能保留每次投标的原始依据和结果文件，又能让不同客户 Excel 的差异主要通过模板配置解决，而不把客户名称写进业务代码。

## 影响

- 2号任务只能在本数据结构上实现匹配、候选与人工选品，不新增 Migration。
- 3号任务按已冻结项目、文件和分页接口开发页面。
- 真实样表到位后，需要新增模板配置和对应测试；这不改变既有项目对旧模板版本的解释。
