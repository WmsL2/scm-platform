# ADR-0059：类型 1 固定语义字段与独立规格复核 Agent

状态：ACCEPTED  
日期：2026-10-13

## 背景

类型 1 与类型 2 都需要解析客户 Excel、召回正式商品、人工确认并回填原表，但业务主条件不同。类型 1 的固定参考字段是三级类目、商品名称、规格型号/规格参数、主要技术要求和限价；客户已填写的行备注、特殊要求及项目备注同样可能包含硬约束。直接复用类型 2 的品牌型号同品逻辑会造成漏推或错推。

## 决策

- 类型 1 使用独立 `Type1Agent`、独立 Pydantic 合同、独立 Prompt 版本和独立匹配编排，不复用类型 2、3、4、5 的业务 Prompt 或选品 Service。
- 未识别类型 1 工作簿时，Agent 只可从真实 Sheet、表头行和表头原文中映射三级类目、商品名称、规格参数、主要技术要求、限价、有效备注及结果回填列；服务端校验后再冻结模板。
- 规格参数与主要技术要求在需求行中合并保存，原始工作簿整行仍保留用于追溯。客户已填写的行备注、特殊要求及项目备注参加复核；空白结果备注不是客户约束。
- 代码负责正式商品及供应商资格、确定性召回、候选落库、限价校验、选品快照和导出；AI 只在服务端候选池内复核类目、名称、规格、技术要求和备注，不得创造商品或候选引用。
- 商品侧字段不存在、字段为空或文本未提及只表示未知，不得据此排除；已有类目、名称、型号、规格、材质、尺寸、功能、包装或备注与客户明确要求冲突时必须排除。
- 数量不参与商品身份判断。品牌默认可替换，只有客户需求或备注明确限定品牌时才成为硬条件。限价属于报价合规条件，不作为商品身份。
- 类型 1 结果进入人工选择状态，不自动选中候选；用户确认后按既有快照与原表回填流程导出。

## 后果

- 类型 1 与类型 2 共享 Excel、正式商品、供应商、价格、任务、快照和导出等底层设施，但业务合同、Prompt 与编排边界保持独立。
- 不新增表、字段或 Alembic Revision；API 路径和权限不变。
- 真实 DeepSeek 与浏览器端上传、显式开始、候选确认、导出和下载仍需验收。
