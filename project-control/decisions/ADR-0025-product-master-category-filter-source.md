# ADR-0025：商品列表类目筛选以商品主数据为候选来源

状态：ACCEPTED  
日期：2026-09-18

## 背景

商品主数据已保存每条正式商品的三级类目路径。此前商品列表的筛选候选项从 `scm_category`
读取，可能显示当前没有任何正式商品使用的类目，也让列表筛选依赖类目维表而非实际商品数据。

## 决策

- 商品列表的一级、二级、三级类目候选项由正式 `scm_product` 三级路径去重生成，不再使用
  `scm_category` 的筛选候选接口。
- 候选项只包含当前商品列表状态中实际可见的路径：正常商品仍要求来源供应商未删除且为 `NORMAL`；
  已停用商品使用已停用列表的可见范围。
- 一级、二级、三级仍可直接输入、远程搜索、多选和分页续载；三级显示完整 `一级 / 二级 / 三级`
  路径，直接选择子级仍回显父级。
- `scm_category` 继续负责独立类目管理；商品编辑和 Excel Confirm 的受控关联已由 ADR-0026
  取消，不再存在 `Product.category_id`。
- Product 路径去重与筛选增加带状态的三级类目组合索引。受 MySQL utf8mb4 索引长度限制，三个
  类目文本列均使用 128 字符索引前缀。

## 结果

- 商品列表不会展示没有结果的类目候选；所有已保存三级路径的商品均可筛选。
- `GET /api/v1/products/category-filter-options` 成为商品列表候选项接口；原
  `GET /api/v1/categories/filter-options` 继续保留给类目维表管理。
